📦 STEP 2: تحديد الموارد (Resources)
1. الشركات (Companies)
المسؤول: وحدة الشركات

الحساسية: متوسطة

الوصول: المالك، المديرون

مصدر: المواصفات الفنية، خرائط سير العمل

2. الموظفون (Employees)
المسؤول: وحدة الموظفين

الحساسية: عالية (PII)

الوصول: HR، المدير المباشر، الموظف نفسه

مصدر: User Stories، واجهات المستخدم

3. العمولات (Commissions)
المسؤول: محرك العمولات

الحساسية: عالية جداً

الوصول: الموظف، المدير، المالية

مصدر: مواصفات API، تدفق العمليات

4. المهام (Tasks)
المسؤول: نظام المهام

الحساسية: متوسطة

الوصول: المشاركون، المديرون

مصدر: واجهة Kanban، خرائط سير العمل

5. الإشعارات (Notifications)
المسؤول: نظام الإشعارات

الحساسية: متوسطة

الوصول: المستلم فقط

مصدر: نظام الإشعارات، تكامل Telegram

6. التكاملات (Integrations)
المسؤول: وحدة التكاملات

الحساسية: عالية (API Keys)

الوصول: المالك، المديرون التقنيون

مصدر: تكامل Shopify/Telegram

7. التقارير (Reports)
المسؤول: وحدة التحليلات

الحساسية: متوسطة

الوصول: حسب الصلاحيات

مصدر: واجهة التقارير

8. الملفات (Files)
المسؤول: نظام التخزين

الحساسية: متفاوتة

الوصول: حسب الصلاحيات

مصدر: مرفقات المهام

9. سجلات التدقيق (Audit Logs)
المسؤول: نظام التدقيق

الحساسية: عالية

الوصول: المالك، المديرون

مصدر: متطلبات الأمان

🔌 STEP 3: تعريف نقاط النهاية
المجموعة A: واجهات المصادقة والهوية
POST /api/v1/auth/login
المصدر: واجهات المستخدم، تسجيل الدخول

الغرض: مصادقة المستخدم

الأمان: Basic Auth

المدخلات: {email, password, company_id}

المخرجات: {access_token, refresh_token, user_data}

رموز الحالة: 200, 401, 403

POST /api/v1/auth/refresh
المصدر: متطلبات الأمان

الغرض: تجديد Access Token

الأمان: Refresh Token Validation

المدخلات: {refresh_token}

المخرجات: {access_token, expires_in}

رموز الحالة: 200, 401

POST /api/v1/auth/companies
المصدر: تدفق تسجيل الدخول

الغرض: الحصول على قائمة الشركات للمستخدم

الأمان: JWT

المخرجات: [{company_id, name, role}]

رموز الحالة: 200, 401

🔐 STEP 4: المصادقة والصلاحيات
نموذج المصادقة:
text
التدفق: JWT + Refresh Tokens
- Access Token: 1 ساعة
- Refresh Token: 30 يوم (HttpOnly Cookie)
- Header: Authorization: Bearer <token>
أنواع الصلاحيات (RBAC):
json
{
  "owner": ["*"],
  "admin": ["company:*", "employees:*", "commissions:*", "tasks:*", "reports:*"],
  "department_manager": ["employees:read", "commissions:read", "commissions:approve", "tasks:*"],
  "finance_manager": ["commissions:*", "reports:financial"],
  "hr_manager": ["employees:*", "departments:*"],
  "employee": ["employees:read:self", "commissions:read:self", "tasks:read", "tasks:write:self"]
}
عزل البيانات:
كل JWT يحتوي company_id

كل استعلام يحتوي WHERE company_id = ?

Row Level Security في PostgreSQL

منع JOINs بين شركات

📡 STEP 6: واجهات داخلية vs خارجية
واجهات داخلية (Internal APIs):
text
- الاتصال: بين وحدات النظام
- أمثلة: Service-to-Service calls
- أمان: API Keys محدودة
- Rate Limiting: عالي
واجهات عامة (Public APIs):
text
- الاتصال: Dashboard، Mobile App
- أمثلة: معظم الـ Endpoints المذكورة
- أمان: JWT + RBAC
- Rate Limiting: حسب خطة الاشتراك
واجهات تكامل (Integration APIs):
text
- الاتصال: Shopify، Telegram، منصات الدفع
- أمثلة: Webhooks، Payment Gateways
- أمان: HMAC، API Keys مخصصة
- Rate Limiting: خاص
حدود الاستخدام:
json
{
  "free_plan": {"per_hour": 1000, "per_day": 10000},
  "business_plan": {"per_hour": 10000, "per_day": 100000},
  "enterprise_plan": {"per_hour": 100000, "per_day": 1000000}
}
⚠️ STEP 7: معالجة الأخطاء
هيكل الخطأ الموحد:
json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "بيانات الإدخال غير صالحة",
    "details": {"field": "amount", "issue": "يجب أن يكون أكبر من الصفر"},
    "request_id": "req_123456",
    "timestamp": "2024-05-20T10:30:00Z"
  }
}
رموز الأخطاء:
400: Bad Request - بيانات غير صالحة

401: Unauthorized - Token مفقود/غير صالح

403: Forbidden - لا صلاحية

404: Not Found - المورد غير موجود

409: Conflict - تكرار/تعارض

422: Unprocessable Entity - بيانات غير قابلة للمعالجة

429: Too Many Requests - تجاوز Rate Limit

500: Internal Server Error

أخطاء أمنية خاصة:
401: عند انتهاء JWT

403: عند محاولة الوصول لبيانات شركة أخرى

429: عند محاولة هجوم Brute Force

استجابة النجاح:
json
{
  "data": {},
  "meta": {
    "timestamp": "2024-05-20T10:30:00Z",
    "request_id": "req_123456"
  },
  "links": {
    "self": "/api/v1/resource",
    "next": "/api/v1/resource?page=2"
  }
}

⚠️ STEP 9: المخاطر والفجوات
الفجوات الحرجة:
1. غياب واجهات المدفوعات
text
السبب: من المحادثة حول التكامل مع منصات الدفع
المشكلة: النظام يوثق الحقوق ولكن لا يدير الدفع
الحل: إضافة:
  POST   /payments              ← إنشاء دفعة
  GET    /payments/{id}         ← تفاصيل الدفع
  POST   /payments/{id}/process ← معالجة الدفع
2. غياب واجهات الملفات
text
السبب: المرفقات في المهام والعمولات
المشكلة: لا توجد واجهة لرفع/تحميل الملفات
الحل: إضافة:
  POST   /files/upload          ← رفع ملف
  GET    /files/{id}            ← تحميل ملف
  DELETE /files/{id}            ← حذف ملف
3. غياب Bulk Operations
text
السبب: الموافقة على عمولات متعددة
