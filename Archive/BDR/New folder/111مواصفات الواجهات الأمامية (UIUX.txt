🎨 مواصفات الواجهات الأمامية (UI/UX Specs) لنظام "باسان"
🎯 الفلسفة التصميمية العامة
المبادئ التصميمية الأساسية:
text
🎨 **بسيط لكن قوي (Simple but Powerful):**
• واجهة نظيفة وغير معقدة
• لكن تخفي قوة النظام الكاملة

👁️ **شفافية كاملة (Full Transparency):**
• كل شيء واضح ومرئي
• لا توجد أسرار أو معلومات مخفية

🚀 **سرعة وتفاعلية (Fast & Responsive):**
• تحميل سريع
• تفاعل فوري
• تجربة سلسة

📱 **مصمم للجوال أولاً (Mobile-First):**
• معظم المستخدمين يستخدمون هواتفهم
• تصميم متجاوب يعمل على كل الأجهزة

🎭 **شخصية لكل دور (Role-Based):**
• كل دور يرى ما يحتاج فقط
• واجهة مخصصة لكل نوع مستخدم

🎭 تجربة المستخدم (UX) والتسلسل
1. تسجيل الدخول والتسجيل:
text
🚀 **التدفق:**
1. صفحة الترحيب:
   • شعار "باسان"
   • "نظامك الذكي للإدارة"
   • [ تسجيل الدخول ] [ إنشاء حساب ]

2. إنشاء حساب شركة:
   • اسم الشركة
   • البلد (السعودية، مصر، الإمارات...)
   • عدد الموظفين (1-10, 11-50, 51+)
   • نوع النشاط (تجارة إلكترونية، خدمات، تعليم...)
   • البريد الإلكتروني وكلمة المرور

3. الإعداد الأولي:
   • إضافة الأقسام الأساسية
   • إدخال بيانات أول موظفين
   • اختيار باقة الاشتراك
   • الربط مع Telegram

✅ **المدة المستهدفة:** 5 دقائق من البداية للنهاية
2. إضافة موظف جديد:
text
👥 **التدفق:**
1. من لوحة التحكم: [ 👥 الموظفون ] → [ + إضافة موظف ]
2. نوع الموظف:
   • دوام كامل
   • دوام جزئي
   • عمولة فقط
3. البيانات الأساسية:
   • الاسم
   • رقم الهاتف
   • البريد الإلكتروني
   • القسم (المبيعات، التسويق...)
4. العقد والعمولات:
   • الراتب الأساسي (إذا وجد)
   • نسبة العمولة
   • نوع العقد
5. الإرسال:
   • يرسل النظام دعوة للموظف عبر Telegram
   • الموظف يربط حسابه

✅ **المدة المستهدفة:** 2 دقيقة لكل موظف
3. حساب عمولة جديدة:
text
💰 **التدفق التلقائي:**
1. وصول بيانات بيع (من Shopify مثلاً)
2. النظام يحدد تلقائياً:
   • المنتج المباع
   • سعره
   • العميل
   • الموظف المسؤول
3. الحساب التلقائي:
   • تطبيق قواعد العمولات
   • حساب المبلغ
   • إرسال إشعار للموظف
4. المراجعة (إذا لزم):
   • إشعار للمدير للمراجعة
   • الموافقة أو الرفض
   • إشعار للموظف بالقرار

✅ **المدة المستهدفة:** 10 ثوانٍ من البيع لحساب العمولة
4. حل نزاع على عمولة:
text
⚖️ **التدفق:**
1. الموظف يضغط على [ ✗ اعتراض ] بجانب عمولة
2. يكتب سبب الاعتراض:
   • "هذا العميل لي، تحدثت معه أولاً"
   • "النسبة غير صحيحة"
   • "المعلومات غير دقيقة"
3. النظام:
   • يجمع البيانات ذات الصلة
   • يقترح حلاً تلقائياً
4. إذا قبل الطرفان ← انتهى النزاع
5. إذا رفض أحدهم ← تحويل للمدير
6. المدير يقرر ← القرار نهائي

✅ **المدة المستهدفة:** حل 80% من النزاعات في 24 ساعة
