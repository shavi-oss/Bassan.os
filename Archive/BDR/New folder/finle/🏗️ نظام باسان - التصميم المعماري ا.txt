تفاصيل النطاقات:
1. نطاق العدالة (Core Domain)
yaml
الهدف التجاري: ضمان العدالة في توزيع الحقوق
الأهمية الاستراتيجية: عالية (هو ما يبيع النظام)
الحساسية: مالية عالية + قانونية عالية
تأثير الفشل: فشل النظام كاملاً

المسؤوليات:
• حساب العمولات بدقة رياضية
• بناء خوارزميات السمعة
• إدارة قواعد التحكيم الآلي
• حفظ إثباتات غير قابلة للتغيير

الكيانات الأساسية:
• CommissionRule (قاعدة العمولة)
• Right (حق)
• ReputationScore (درجة سمعة)
• Dispute (نزاع)
2. نطاق الإنجاز (Supporting Domain)
yaml
الهدف التجاري: توثيق الإنجازات والأدلة
الأهمية الاستراتيجية: متوسطة
الحساسية: تشغيلية متوسطة
تأثير الفشل: عدم القدرة على إثبات الحقوق

المسؤوليات:
• إدارة دورة حياة المهمة
• ربط الأدلة بالإنجازات
• تقييم جودة الإنجاز
• تخزين وتنظيم المستندات
3. نطاق التحقق (Supporting Domain)
yaml
الهدف التجاري: التحقق من تنفيذ الالتزامات
الأهمية الاستراتيجية: عالية
الحساسية: مالية عالية
تأثر الفشل: احتيال، خسائر مالية

المسؤوليات:
• التحقق من المدفوعات الخارجية
• مطابقة الحقوق بالمدفوعات
• اكتشاف التناقضات
• بناء سلسلة الإثباتات
4. نطاق التواصل (Supporting Domain)
yaml
الهدف التجاري: إدارة الاتصال بين الأطراف
الأهمية الاستراتيجية: منخفضة
الحساسية: خصوصية متوسطة
تأثير الفشل: تأخر في الاتصال

المسؤوليات:
• إرسال الإشعارات
• إدارة التفضيلات
• تسجيل التفاعل
• دعم قنوات متعددة
5. نطاق الهوية (Generic Domain)
yaml
الهدف التجاري: إدارة الوصول والصلاحيات
الأهمية الاستراتيجية: عالية
الحساسية: أمنية عالية
تأثير الفشل: اختراق النظام

المسؤوليات:
• المصادقة والتخويل
• إدارة الجلسات
• تطبيق سياسات الوصول
• تسجيل أنشطة الوصول
6. نطاق التكامل (Generic Domain)
yaml
الهدف التجاري: التواصل مع الأنظمة الخارجية
الأهمية الاستراتيجية: متوسطة
الحساسية: أمنية متوسطة
تأثير الفشل: فقدان البيانات من المصادر الخارجية

المسؤوليات:
• إدارة APIs الخارجية
• معالجة Webhooks
• تحويل تنسيقات البيانات
• إدارة مفاتيح API
7. نطاق التحليلات (Generic Domain)
yaml
الهدف التجاري: تحويل البيانات إلى رؤى
الأهمية الاستراتيجية: منخفضة
الحساسية: خصوصية متوسطة
تأثير الفشل: فقدان الرؤى التحليلية

المسؤوليات:
• معالجة البيانات
• توليد التقارير
• اكتشاف الأنماط
• تقديم التوصيات

قواعد الاتصال بين السياقات:
1. نمط الاتصال:
yaml
النمط: Event-Driven مع REST APIs للاستعلامات
المبدأ: "كل سياق يملك بياناته، ويتواصل عبر أحداث"

الاتصال المسموح:
• JusticeContext ← AchievementContext (استعلام عن الإنجازات)
• JusticeContext ← VerificationContext (استعلام عن التحقق)
• جميع السياقات → IdentityContext (للتحقق من الصلاحيات)
• جميع السياقات → NotificationContext (لإرسال الإشعارات)

الاتصال الممنوع:
• أي سياق يصل مباشرة لقاعدة بيانات سياق آخر
• أي سياق يعدل بيانات سياق آخر مباشرة
2. نماذج البيانات المستقلة:
yaml
مثال: مفهوم "الموظف" يختلف بين السياقات:
• في JusticeContext: Employee {id, commission_rules, rights_history}
• في AchievementContext: Employee {id, skills, current_tasks}
• في VerificationContext: Employee {id, payment_accounts, verification_history}

كل سياق يحتفظ بالتمثيل المناسب لاحتياجاته
3. حدود السياقات بوضوح:
سياق العدالة (JusticeContext) يفعل:

yaml
✅ يحسب الحقوق بناءً على قواعد
✅ يبني درجات السمعة
✅ يدير النزاعات والتحكيم
✅ ينشر أحداث عن تغيرات الحقوق

❌ لا يتحقق من المدفوعات
❌ لا يوثق المهام
❌ لا يخزن ملفات المستندات
❌ لا يدير التكاملات الخارجية
سياق التحقق (VerificationContext) يفعل:

yaml
✅ يتصل بمنصات الدفع للتحقق
✅ يطابق المعاملات مع الحقوق
✅ يكتشف التناقضات
✅ يبني سلاسل إثبات

❌ لا يحسب الحقوق
❌ لا يبني السمعة
❌ لا يدير المهام
❌ لا يتخذ قرارات تحكيم
سياق الهوية (IdentityContext) يفعل:

yaml
✅ يتحقق من هوية المستخدمين
✅ يطبق سياسات الصلاحيات
✅ يدير الجلسات
✅ يسجل أنشطة الوصول

❌ لا يعرف أي شيء عن الأعمال
❌ لا يصل لبيانات الأعمال المباشرة
❌ لا يشارك في عمليات الأعمال
🎯 PHASE 3 — C4 LEVEL 1: السياق النظامي
النظام كصندوق أسود:
text
اسم: "نظام باسان"
وصف: منصة عدالة رقمية للشركات العربية تربط بين الشركات والموظفين
بطريقة عادلة وشفافة بدون وساطة مالية.

مبدأ التشغيل: "نحن نحسب الحقوق، نتحقق من التنفيذ، نبني السمعة
لكن الأموال تتدفق مباشرة بين الأطراف."
الممثلون الأساسيون:
مستخدمون بشريون:
yaml
1. صاحب الشركة (Company Owner):
   • الصلاحية: المالك الكامل لبيانات شركته
   • الثقة: عالية (يدفع اشتراكاً)
   • التوقعات: عدالة وشفافية

2. المدير (Manager):
   • الصلاحية: قسمه فقط
   • الثقة: متوسطة
   • التوقعات: أدوات إدارة عادلة

3. الموظف (Employee):
   • الصلاحية: بياناته فقط
   • الثقة: متوسطة (يستخدم النظام مجاناً)
   • التوقعات: حماية حقوقه

4. مدير النظام (System Admin):
   • الصلاحية: تقنية فقط
   • الثقة: عالية جداً
   • التوقعات: استقرار وأمان
أنظمة خارجية:
yaml
1. Shopify:
   • الثقة: متوسطة (مصدر بيانات)
   • البيانات: معلومات المبيعات
   • الحماية: HMAC verification

2. Telegram:
   • الثقة: متوسطة (قناة تواصل)
   • البيانات: إشعارات وأوامر
   • الحماية: API Tokens

3. منصات الدفع (PayMob/Stripe):
   • الثقة: متوسطة (للتحقق فقط)
   • البيانات: حالة المعاملات
   • الحماية: API Keys + IP Whitelisting

4. Google Drive:
   • الثقة: منخفضة (تخزين ملفات)
   • البيانات: ملفات العمل
   • الحماية: OAuth 2.0 + محدودية الصلاحيات

افتراضات الأمان:
yaml
1. الأنظمة الخارجية ليست خبيثة ولكن قد تتعطل

تفاصيل الحاويات:
1. 🌐 تطبيق الويب (Web Application)
yaml
المسؤولية: واجهة المستخدم الرئيسية
التقنية: React + Next.js (SSR)
البيانات: لا يخزن بيانات حساسة
الأمان:
  • JWT في HttpOnly Cookies
  • CSP Headers
  • XSS/CSRF Protection
  • لا بيانات حساسة في LocalStorage
2. 📱 تطبيق الموبايل (Mobile App)
yaml
المسؤولية: واجهة الموظفين الميدانية
التقنية: React Native
البيانات: تخزين محلي مشفر
الأمان:
  • Biometric Authentication
  • Encrypted Storage
  • Certificate Pinning
  • Remote Wipe Capability
3. 🤖 بوت Telegram (Telegram Bot)
yaml
المسؤولية: قناة سريعة للموظفين
التقنية: Node.js + Telegram Bot API
البيانات: معرفات المستخدمين فقط
الأمان:
  • Telegram User ID Authentication
  • Rate Limiting per User
  • Command Validation
  • No Sensitive Data in Chats
4. 🚪 بوابة API (API Gateway)
yaml
المسؤولية: نقطة الدخول الوحيدة
التقنية: Kong/Envoy
البيانات: Headers + Request/Response
الأمان:
  • JWT Validation
  • Rate Limiting (per tenant/user)
  • IP Whitelisting (for external systems)
  • DDoS Protection
  • Request/Response Logging (sanitized)
5. ⚖️ خدمة العدالة (Justice Service)
yaml
المسؤولية: قلب النظام - حساب الحقوق والسمعة
التقنية: Node.js/Go
البيانات: حقوق، قواعد، سمعة، نزاعات
الأمان:
  • Tenant Isolation (database level)
  • Input Validation (commission rules)
  • Audit Logging (all calculations)
  • Digital Signing (all outputs)
6. 🏆 خدمة الإنجاز (Achievement Service)
yaml
المسؤولية: إدارة المهام والأدلة
التقنية: Node.js/Java
البيانات: مهام، تسليمات، أدلة، مراجعات
الأمان:
  • File Upload Validation
  • Malware Scanning
  • Access Control (who can view evidence)
  • Evidence Chain Preservation
7. 🔍 خدمة التحقق (Verification Service)
yaml
المسؤولية: التحقق من المدفوعات الخارجية
التقنية: Python/Node.js
البيانات: معاملات، كشوفات، نتائج تحقق
الأمان:
  • API Key Management (for external systems)
  • PII Masking (in logs)
  • Idempotency Keys (for payment verification)
  • Fraud Detection Rules
8. 🔑 خدمة الهوية (Identity Service)
yaml
المسؤولية: إدارة الوصول والمصادقة
التقنية: Node.js + Redis
