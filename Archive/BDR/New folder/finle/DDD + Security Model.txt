2.2 نموذج التحكم في الوصول (Access Control Model)
نموذج RBAC + ABAC الهجين:
yaml
RBAC Layer (الدور):
• Owner: صلاحيات كاملة
• Admin: صلاحيات إدارية
• Manager: صلاحيات قسمية
• Employee: صلاحيات شخصية
• System: صلاحيات تقنية

ABAC Layer (السمات):
• company_id: الشركة المالكة
• department_id: القسم التابع
• employment_status: حالة التوظيف
• reputation_score: درجة السمعة
• subscription_plan: خطة الاشتراك
مصفوفة الصلاحيات (Permission Matrix):
yaml
Commission Context:
• Create: Owner, Admin, System
• Read: Owner, Admin, Manager (قسمه), Employee (خاصته)
• Update: Owner, Admin, Manager (قسمه)
• Delete: Owner, Admin, System
• Approve: Owner, Admin, Manager (حسب الحدود)

Task Context:
• Create: Owner, Admin, Manager
• Assign: Owner, Admin, Manager
• Update: Owner, Admin, Manager, Employee (مهامه)
• Complete: Employee (مهامه)
• Review: Owner, Admin, Manager

Evidence Context:
• Upload: Owner, Admin, Manager, Employee (أدلته)
• Verify: Owner, Admin, Manager, System
• Delete: System فقط (للأرشفة)
قواعد الصلاحيات الديناميكية:
javascript
class AccessControlPolicy {
  canViewCommission(user, commission) {
    return (
      // RBAC Check
      user.hasRole(['owner', 'admin']) ||
      
      // ABAC Check - Same Department
      (user.hasRole('manager') && 
       user.department_id === commission.employee.department_id) ||
      
      // ABAC Check - Own Commission
      (user.hasRole('employee') && 
       user.id === commission.employee_id) ||
      
      // Reputation-based Access
      (user.reputation_score >= 4.5 && 
       commission.amount < user.reputation_based_limit)
    );
  }
  
  canApproveCommission(user, commission) {
    const approvalLimits = {
      manager: 50000,
      admin: 200000,
      owner: Infinity
    };
    
    return (
      user.hasRole(['owner', 'admin', 'manager']) &&
      commission.amount <= approvalLimits[user.role] &&
      user.department_id === commission.employee.department_id
    );
  }
}

خدمة التوقيع المشفرة (Cryptographic Signing Service):

interface CryptographicSigner {
  // توقيع البيانات
  signData(data: any, keyId: string): SignedData;
  
  // التحقق من التوقيع
  verifySignature(signedData: SignedData): VerificationResult;
  
  // توليد Hash
  generateHash(data: any): string;
  
  // حفظ الإثبات
  storeProof(proof: CryptographicProof): string;
}

class CommissionSigner {
  async signCommission(commission: Commission) {
    // 1. توليد Hash للعمولة
    const commissionHash = this.generateHash({
      id: commission.id,
      amount: commission.amount,
      employeeId: commission.employeeId,
      calculationRules: commission.calculationRules
    });
    
    // 2. التوقيع الرقمي
    const signature = await this.signData(commissionHash, 'commission-key');
    
    // 3. حفظ في سلسلة الكتل
    const proofId = await this.storeProof({
      type: 'commission_calculation',
      dataHash: commissionHash,
      signature: signature,
      timestamp: new Date(),
      signedBy: 'system'
    });
    
    return { commissionHash, signature, proofId };
  }
}
2.6 نموذج اكتشاف الشذوذ (Anomaly Detection Model)
أنماط الشذوذ المراقبة:
yaml
النمط 1: شذوذ الوصول
• محاولات وصول من أماكن غير معتادة
• معدل فشل مصادقة مرتفع
• وقت وصول غير طبيعي

النمط 2: شذوذ البيانات
• قيم غير متوقعة في الحسابات
• أنماط مبيعات غير طبيعية
• تغييرات مفاجئة في الأداء

النمط 3: شذوذ السلوك
• تغييرات مفاجئة في عادات العمل
• تفاعلات غير معتادة مع النظام
• محاولات تجاوز الصلاحيات

النمط 4: شذوذ النظام
• زيادة غير طبيعية في الحمل
• أخطاء غير مألوفة
• تغييرات في الأداء
خدمة اكتشاف الشذوذ (Anomaly Detection Service):
python
class AnomalyDetector:
    def __init__(self):
        self.models = {
            'access_pattern': AccessPatternModel(),
            'commission_pattern': CommissionPatternModel(),
            'behavior_pattern': BehaviorPatternModel(),
            'system_pattern': SystemPatternModel()
        }
    
    def detect_anomalies(self, context, data):
        anomalies = []
        
        # التحقق من أنماط الوصول
        if self.models['access_pattern'].is_anomalous(data['access_data']):
            anomalies.append({
                'type': 'access_anomaly',
                'severity': 'high',
                'description': 'نمط وصول غير طبيعي'
            })
        
        # التحقق من أنماط العمولات
        if self.models['commission_pattern'].is_anomalous(data['commission_data']):
            anomalies.append({
                'type': 'commission_anomaly',
                'severity': 'critical',
                'description': 'نمط عمولات مشبوه'
            })
        
        return anomalies
2.7 نموذج الاستجابة للحوادث (Incident Response Model)
خطة الاستجابة:
yaml
المستوى 1: حوادث منخفضة الخطورة
• الاستجابة: تشغيل Alerting تلقائي
• الإجراء: تسجيل وتتبع
• الوقت المستهدف: < 1 ساعة

المستوى 2: حوادث متوسطة الخطورة
• الاستجابة: تنبيه الفريق الأمني
• الإجراء: عزل وتحقيق
• الوقت المستهدف: < 4 ساعات

المستوى 3: حوادث عالية الخطورة
• الاستجابة: تشغيل خطة الطوارئ
• الإجراء: احتواء واستعادة
• الوقت المستهدف: < 1 ساعة

المستوى 4: حوادث حرجة
• الاستجابة: تنبيه الإدارة العليا
• الإجراء: اتصال بالسلطات
• الوقت المستهدف: فوري
خطوات الاستجابة التفصيلية:
text
1. الاكتشاف (Detection):
   • Monitoring Systems
   • Anomaly Detection
   • User Reports

2. التقييم (Assessment):
   • تحديد النطاق
   • تقييم الأثر
   • تصنيف الحادث

3. الاحتواء (Containment):
   • عزل الأنظمة المتأثرة
   • تغيير الصلاحيات
   • تنفيذ إجراءات طارئة

4. الاستئصال (Eradication):
   • إزالة سبب الحادث
   • تطبيق إصلاحات
   • تأمين الأنظمة

5. الاستعادة (Recovery):
   • استعادة البيانات
   • إعادة الخدمة
   • المراقبة المعززة

6. التعلم (Lessons Learned):

// في كل سياق، حقن خدمة التحقق
class CommissionContext {
  constructor(
    private commissionRepository: CommissionRepository,
    private securityVerifier: SecurityVerifier,
    private auditLogger: AuditLogger
  ) {}
  
  async calculateCommission(saleData: SaleData): Promise<Commission> {
    // 1. التحقق الأمني قبل العملية
    await this.securityVerifier.verifyAccess(
      currentUser(),
      'calculate_commission',
      { saleData }
    );
    
    // 2. تنفيذ منطق المجال
    const commission = this.calculate(saleData);
    
    // 3. التحقق الأمني بعد العملية
    await this.securityVerifier.verifyIntegrity(commission);
    
    // 4. تسجيل التدقيق
    await this.auditLogger.log({
      action: 'commission_calculated',
      entity: commission,
      user: currentUser(),
      timestamp: new Date()
    });
    
    return commission;
  }
}

// سياسات الأمان كقواعد مجال
class SecurityPolicies {
  // سياسة فصل المهام
  static ensureSegregationOfDuties(
    user: User, 
    action: string, 
    context: any
  ): boolean {
    const conflictingRoles = {
      'approve_commission': ['calculate_commission'],
      'verify_payment': ['receive_payment'],
      'audit_logs': ['modify_logs']
    };
    
    return !user.hasAnyRole(conflictingRoles[action] || []);
  }
  
  // سياسة الحدود المالية
  static checkFinancialLimits(
    user: User,
    amount: number,
    action: string
  ): boolean {
    const limits = {
      'manager': { 'approve_commission': 50000 },
      'admin': { 'approve_commission': 200000 },
      'owner': { 'approve_commission': Infinity }
    };
    
    const userLimit = limits[user.role]?.[action];
    return amount <= userLimit;
  }
}

// طبقة عزل لعمليات الأمان الخارجية
class SecurityACL {
  async verifyExternalPayment(paymentData: any): Promise<VerificationResult> {
    // 1. تحويل التنسيق الخارجي للتنسيق الداخلي
    const internalData = this.transformToInternalFormat(paymentData);
    
    // 2. تطبيق قواعد التحقق الداخلية
    const validationResult = this.validateInternalData(internalData);
    
    // 3. التحقق من النزاهة
    const integrityCheck = this.checkDataIntegrity(internalData);
    
    // 4. إرجاع النتيجة المعيارية
    return {
      verified: validationResult.valid && integrityCheck.passed,
      confidence: this.calculateConfidence(validationResult, integrityCheck),
      evidence: this.collectEvidence(internalData)
    };
  }
}
النمط 2: Domain Events للأمان

// أحداث المجال التي تثير استجابات أمنية
class SecurityAwareDomainEvents {
  // حدث حساب عمولة يثير تحقق أمني
  @DomainEvent()
  commissionCalculated(commission: Commission) {
    // تشغيل تحقق الشذوذ
    this.anomalyDetector.checkCommissionPattern(commission);
    
    // تحديث تحليل المخاطر
    this.riskAnalyzer.updateRiskProfile(commission.employee);
    
    // تسجيل للتدقيق
    this.auditService.logCommissionCalculation(commission);
  }
  
  // حدث وصول مرفوض يثير استجابة
  @DomainEvent()
  accessDenied(user: User, resource: string, reason: string) {
    // تحديث سمعة المستخدم
    this.reputationService.adjustScore(user, -10, 'access_denied');
    
    // تشغيل اكتشاف الشذوذ
    this.anomalyDetector.detectAccessPattern(user, resource);
    
    // إشعار فريق الأمن إذا تكرر
    if (this.isRepeatedAttempt(user, resource)) {
      this.securityTeam.notify({
        type: 'suspicious_access',
        user: user,
        attempts: this.getAttemptCount(user, resource)
      });
    }
  }
}
