📘 وثيقة النظام الكاملة - نظام "باسان"
🎯 المستند الرئيسي: نظرة شاملة على النظام
📄 وثيقة تعريف نظام "باسان" (Basan System Blueprint)
🏛️ الفصل 1: نظرة عامة على النظام
1.1 ما هو نظام "باسان"؟
text
نظام "باسان" هو منصة SaaS عربية متعددة المستأجرين مصممة خصيصاً للشركات الناشئة والمتوسطة. يجمع النظام بين إدارة الموارد البشرية، نظام العمولات الذكي، الأتمتة الذكية لسير العمل، والتكامل مع أدوات العمل اليومية في نظام واحد موحد.
1.2 الفلسفة الأساسية
text
"عدالة وشفافية في العلاقات الوظيفية بدون وساطة مالية"
1.3 القيمة المقترحة
yaml
للشركات:
• توفير 8-12% من الإيرادات المسربة (أخطاء حساب العمولات)
• توفير 30-40 ساعة عمل إدارية شهرياً
• زيادة إنتاجية الفرق بنسبة 30-40%
• تخفيض دوران الموظفين بنسبة 50%

للموظفين:
• وضوح كامل في الحقوق والاستحقاقات
• حماية من الظلم والتلاعب
• مسار تطوير وظيفي واضح
• نظام تحكيم سريع وعادل

للسوق العربي:
• معيار جديد للعدالة في بيئة العمل
• سوق شفاف يكافئ الملتزمين
• نمو اقتصادي مبني على الثقة
1.4 المشكلة الأساسية التي نحلها
text
الشركات العربية الناشئة تخسر 8-12% من إيراداتها في أخطاء حساب العمولات، وتهدر 30-40 ساعة عمل شهرياً في الفوضى الإدارية، وتعاني من ارتفاع دوران الموظفين بسبب غياب العدالة والشفافية.
1.5 الحل الفريد
text
نظام واحد يدير كل عمليات الشركة (الموظفين، العمولات، المهام، التواصل، التحليل) مع تكيف ذكي مع خصوصيات كل شركة، مع الحفاظ على مبدأ "لا وساطة مالية" - الأموال تتدفق مباشرة بين الأطراف.

4.2 تدفق البيانات بين المكونات
text
سيناريو: عملية بيع جديدة من Shopify

1. Shopify Store → Webhook
   • حدث: order_created
   • بيانات: {order_id, amount, customer_email}

2. Webhook → Integration Service
   • التحقق من التوقيع
   • تحويل التنسيق
   • تخزين في Redis Queue

3. Integration Service → Message Queue
   • حدث: NEW_SALE_EVENT

4. Message Queue → [Commission Service + Task Service + Analytics Service]
   • كل خدمة تعالج حسب دورها

5. Commission Service:
   • البحث عن الموظف المسؤول
   • تطبيق قواعد العمولات
   • حساب المبلغ
   • تخزين في PostgreSQL

6. Communication Service:
   • إشعار للموظف: "مبروك! عمولة جديدة"
   • تحديث للمدير
4.3 هيكل قواعد البيانات العلائقية
sql
الجدول الرئيسي: الموظفون (employees)
• employee_id (PK)     - معرف فريد
• company_id (FK)      - الشركة التابع لها
• full_name            - الاسم الكامل
• contract_type        - نوع العقد
• base_salary          - الراتب الأساسي
• commission_rate      - نسبة العمولة

الجدول الرئيسي: العمولات (commissions)
• commission_id (PK)   - معرف فريد
• employee_id (FK)     - الموظف المستحق
• sale_id             - عملية البيع
• amount              - مبلغ العمولة
• status              - الحالة

الجدول الرئيسي: المهام (tasks)
• task_id (PK)        - معرف فريد
• employee_id (FK)    - الموظف المسؤول
• title               - عنوان المهمة
• status              - الحالة
• due_date            - الموعد النهائي

الجدول الرئيسي: الشركات (companies)
• company_id (PK)     - معرف فريد
• name                - اسم الشركة
• subscription_plan   - خطة الاشتراك
• settings            - الإعدادات المخصصة
🔄 الفصل 5: تدفق العمل والعمليات
5.1 تدفق إضافة موظف جديد
text
1. المدير يريد إضافة موظف
2. إنشاء حساب أساسي (بيانات أساسية، قسم، عقد)
3. إرسال دعوة للموظف (Telegram/إيميل)
4. الموظف يقبل الدعوة ويكمل ملفه
5. التفعيل النهائي (حسابات فرعية، إشعارات)
6. الموظف جاهز للعمل
5.2 تدفق عملية البيع إلى دفع العمولة
text
1. حدث البيع (من Shopify)
2. استقبال وتوثيق الحدث
3. تحديد المسؤولين (مندوب، مساهمين)
4. حساب العمولات (قواعد، تعديلات، حدود)
5. المراجعة والموافقة (عرض للموظف، موافقة مدير)
6. جدولة الدفع (دفعات شهرية، ضرائب، عملات)
7. نهاية العملية (التخزين، التحليل، جاهز للدفع)
5.3 تدفق دورة حياة المهمة الكاملة
text
1. إنشاء المهمة (من مدير أو تلقائياً)
2. تحليل المهمة وتصنيفها (نوع، صعوبة، وقت)
3. توزيع المهمة (بحث عن الموظفين المناسبين)
4. التنفيذ والمتابعة (استلام، رفع تقدم، تتبع)
5. المراجعة والتسليم (رفع تسليم، مراجعة مدير)
6. الإغلاق والتعلم (تسجيل النتائج، تحليل الأداء)
5.4 تدفق نظام التواصل والإشعارات
text
1. حدث يحتاج إشعار (بيع، مهمة، اجتماع)
2. تحليل الحدث وتحديد المستلمين
3. التخصيص حسب المستلم (تفضيلات، قنوات)
4. إعداد المحتوى (رسالة، معلومات، روابط)
5. الإرسال عبر القنوات (Telegram، التطبيق، إيميل)
6. التتبع والتعلم (وصول، فتح، رد، تحسين)
5.5 تدفق حل نزاع العمولات
text
1. بداية النزاع (موظف يعترض على عمولة)
2. تسجيل النزاع (أسباب، وقت، رقم تتبع)
3. جمع الأدلة (بيانات، سجلات، قواعد)
4. التحكيم الآلي الأولي (تحليل باستخدام القواعد)
5. عرض الحل على الطرفين (موافقة أو رفض)
6. التحكيم البشري (إذا رفض أحد الطرفين)
7. تنفيذ القرار (تعديل العمولات، إشعارات)
8. التعلم والتطوير (حفظ النزاع، تحسين القواعد)
🛡️ الفصل 6: نظام الأمان والصلاحيات
6.1 مستويات الصلاحيات (RBAC)
yaml
1. المالك (Owner):
   • صلاحيات كاملة على كل شيء
   • يمكنه تعديل أي إعداد
   • يرى كل البيانات

2. المدير (Manager):
   • صلاحيات على قسمه فقط
   • يمكنه إدارة موظفي قسمه
   • يرى بيانات قسمه فقط

3. الموظف (Employee):
   • صلاحيات محدودة
   • يرى بياناته فقط
   • يمكنه إجراء مهام محددة

4. النظام (System):
   • صلاحيات تقنية
   • وصول للبيانات لأغراض التشغيل
   • لا يمكنه تعديل بيانات المستخدمين
6.2 تدفق المصادقة والصلاحيات
text
1. المستخدم → Frontend → Auth Service
2. توليد JWT Token
3. API Gateway (يتحقق من التوكن في كل طلب)
4. Role-Based Access Control
5. Permission Check
6. الخدمة المستهدفة
6.3 حدود الأمان
yaml
1. حدود الثقة الخارجية:
   • HMAC Verification for Shopify Webhooks
   • API Keys for External Integrations
   • TLS 1.3 for all external communications

2. حدود عزل المستأجرين:
   • Row-Level Security في PostgreSQL
   • Company ID في كل API call
   • لا تسرب بيانات بين الشركات

text

• إدارة الملف الشخصي

الإشعارات:
• عمولات جديدة
• مهام جديدة

• تحديثات نظامية
7.3 تكامل مع منصات الدفع (PayMob/Stripe)
text
نموذج العمل:
• النظام لا يلمس الأموال
• الشركة تدفع مباشرة للموظف
• النظام يتحقق فقط من حدوث الدفع

طرق التحقق:
1. API Integration (الاتصال المباشر)
2. Webhook Integration (إشعارات من المنصة)
3. Bank Statement Upload (كشوفات الحسابات)
7.4 تكامل مع Google Drive
text
نموذج العمل:
• الملفات لا تخزن على النظام
• كل شركة تربط حساب Google Drive الخاص بها
• الموظفون يرفعون الملفات على درايف الشركة
• النظام يولد روابط آمنة للملفات

الفائدة:
• الشركة تتحكم في ملفاتها
• النظام لا يتحمل تكاليف التخزين
• يمكن التحقق من تسليم المهام وجودتها
💰 الفصل 8: نموذج العمل والإيرادات

yaml
1. اشتراكات شهرية (SaaS):

   • تكامل API متقدم: 199 ريال/شهر
   • تقارير متقدمة: 99 ريال/شهر
   • نظام النزاعات السريع: 149 ريال/شهر

3. رسوم لمرة واحدة:
   • الإعداد الأولي: 500 ريال
   • تدريب الفريق: 1000 ريال
   • تكامل مخصص: حسب التعقيد
8.2 إعفاءات وحوافز
yaml
1. سنة أولى مجانية للشركات الناشئة (< 5 موظفين)
2. خصم 20% للدفع السنوي
3. خصم 15% للجهات الحكومية والتعليمية
4. مجاني للموظفين (دائماً)
8.3 التكاليف المتوقعة
yaml
1. التطوير التقني: 500,000 دولار (السنة الأولى)
2. التشغيل والسحابة: 50,000 دولار/سنوياً
3. التسويق والمبيعات: 200,000 دولار (السنة الأولى)
4. فريق العمل: 300,000 دولار/سنوياً

الإجمالي الأولي: 1,050,000 دولار
8.4 نقطة التعادل
yaml
